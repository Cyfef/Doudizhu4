# 欢乐四人斗地主（两副牌 · PC 网页版 · 积分不封顶）

基于设计文档 V9.0 实现的本地多人斗地主。4 人一桌、两副牌（108 张）、1 名地主打 3 名农民，
单局积分不封顶、允许负分，房间内独立排行榜，仅限同一局域网内游玩。

---

## 一、环境要求

- 已安装 **Node.js 16+**（无需任何第三方依赖，服务端零安装）。
- 一台作为服务器的电脑（Windows 或 WSL 均可），同一局域网下的其他设备通过浏览器加入。
- 现代浏览器（Chrome / Edge / Firefox / Safari）。

---

## 二、如何运行

### 方式 A：Windows 直接运行

双击根目录的 **`start-host.bat`** 即可启动服务（首次运行前，请先右键 **`allow-firewall.bat` → 以管理员身份运行** 放行一次防火墙，否则手机/平板连不上）。
启动窗口会自动打印本机各网卡 IP，手机/平板请用「以太网/WLAN」那个 IPv4 访问。

也可以手动在终端（PowerShell 或 CMD）运行：

```bash
npm start
# 或
node server/index.js
```

> 端口默认 `8080`，可用环境变量 `PORT` 覆盖（如 `set PORT=9000` 后再双击，或 `PORT=9000 node server/index.js`）。

### 方式 B：Linux / macOS 直接运行

在终端进入项目目录：

```bash
chmod +x start.sh
./start.sh
# 或自定义端口： PORT=9000 ./start.sh
```

### 跑测试

项目自带 5 组回归测试（只用 Node 内置能力，**不需要装任何依赖**，共 113 项断言）：

```bash
npm test
```

| 用例 | 覆盖内容 |
|---|---|
| `test/deal.test.js` | 发牌算法：张数守恒/唯一性、单槽位同号点 ≤4 张、王不进底牌、**炸弹总数落在 [10,20] 且均值 ≈15**、**火箭率 ≈10%**、**「谁当地主炸弹数都一样」的并牌不变量** |
| `test/bot.test.js` | 人机引擎：出法枚举与暴力枚举对拍、牌型合法性、牌力分布与叫分/加倍阈值校准、四机 600 局冒烟 |
| `test/room-bot.test.js` | 房间人机：座位增删权限、房主转让不落到人机、1 真人 + 3 人机整房自动跑完、调度不堆积定时器 |
| `test/http-bot.test.js` | 真实 HTTP 端到端：在 8199 端口起服务端，走 `/api/bot` 加人机，用 SSE 看着一局打完到结算 |
| `test/ui-bot.test.js` | 客户端 UI：座位卡上的人机按钮与请求体、牌桌机器人标记（需要 jsdom；未装时自动跳过） |

> `NODE_PATH=<有 jsdom 的 node_modules 路径> node test/ui-bot.test.js`

### 局域网内其他设备加入

1. 服务器电脑上启动服务端，记下启动日志打印的「本机局域网 IP」。
2. **同一 Wi-Fi / 同一路由器 / 同一网段**下的其他设备，浏览器打开 `http://<本机局域网IP>:8080`。
3. 输入房间昵称后，创建房间或输入 6 位房间号 + 密码加入。

> **局域网访问必读**
> - 服务绑定 `0.0.0.0`（所有网卡），无需任何端口转发。
> - **Windows 防火墙必须放行 8080 入站**：首次请用根目录的 `allow-firewall.bat`（右键以管理员运行）添加规则；手动命令：
>   `New-NetFirewallRule -DisplayName DDZ_Server_8080 -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Private,Public`
> - Linux 若启用了 `firewalld` / `ufw`，需放行 8080（如 `sudo ufw allow 8080`）；macOS 一般无需额外设置。
> - 手机和电脑要在**同一个网段**：电脑连以太网、手机连 WiFi 时，多数家用路由器把它们放同一网段；若被划到访客网络或开启设备隔离，设备间就不通，页面会一直打不开（需从路由器侧解决）。
> - 不要访问 `172.x.x.x`、`192.168.x.x` 等**其它设备/虚拟网卡**的地址——要用**服务器电脑自身**「以太网/WLAN」适配器下显示的 IPv4。

## 三、游戏玩法

1. **首页**：输入本房间内唯一的昵称 → 「创建房间」或「加入房间」。
   若通过别人的**邀请链接**打开（`...?room=123456`），会预填房间号；本地已有昵称时直接自动加入。
2. **创建房间**可设置：房间名称、底分、总局数（1–50）、出牌倒计时（5–30 秒）、密码（可选）、是否允许明牌、是否允许加倍/超级加倍。
3. **房间等待页**：4 人满员后，房主点「开始游戏」。房主可踢人、转让房主、解散房间。
   凑不满人时，房主可以直接在**空座位上放人机**补位（详见「七、人机（AI 对手）」）。
4. **单局流程**：
   叫分（不叫 / 1 / 2 / 3 分，叫 3 分立即当地主，从上一局赢家先叫）→ 确定地主、公开底牌 →
   明牌（仅地主可选，×2）→ 加倍阶段（**全员同时选择**，不排队）→
   地主先出 → 轮流出牌/过牌 → 有人出完 → 结算 → 下一局。
   - **加倍阶段是并发的**：4 个人各自点各自的（不加倍 / 加倍×2 / 超级加倍×4），谁先谁后都行、互不阻塞；
     自己选完按钮就收起来，只剩一行「你已选择「加倍 ×2」　已选 3 / 4，等待其他玩家…」，在局玩家全部选完立刻进入出牌阶段（不等倒计时）。
5. **出牌操作**：鼠标或触摸点选手牌；牌桌底部依次显示「不要 / 提示 / 出牌」，首出时不能“不要”。提示按钮为黄色，“不要/要不起”为浅绿色。
6. **看谁出了什么**：每位玩家打出的牌显示在其座位旁的出牌区域，牌面重叠排列；移动端“不要”也显示在相同位置。自己的出牌显示在牌桌靠近自己的一侧。
7. **结算 / 最终榜**：每局结束弹窗展示倍数与积分变动；达到总局数后展示最终排行榜，全员自动退出。
7. **看规则**：牌桌顶栏 **📨 邀请 → 📖 规则 → 🔊 音量** 中间的 **📖 规则** 按钮会弹出完整玩法说明
   （牌与人数、牌型表、比牌、一局流程、倍数与积分、超时与断线），滚动查看、点「知道了」关闭；
   规则内容与下面的「四、规则要点」完全一致，随时可查，不用翻文档。

## 四、规则要点（与设计文档一致）

- **牌组**：两副牌 108 张，4 张王（2 大 2 小），每人 25 张、底牌 8 张，地主共 33 张。
- **合法牌型**：单张、对子、三张、三带二、顺子（≥5 连续单牌，不含 2 和王）、连对（≥3 连续对）、
  飞机（≥2 连续三张）、飞机带对、炸弹（4–8 张同点）、火箭（4 张王）。两个小王或两个大王可作为对子，也可作为飞机的翼对子；一大王加一小王不是对子。王不能作为三带二的对子。
  **删除**：三带一、飞机带单、四带二、四带两对；炸弹不可带牌。
- **炸弹/火箭倍率**：4 张 ×2、5 张 ×4、6 张 ×8、7 张 ×16、8 张 ×32；火箭 ×2。多个相乘，不封顶。
- **春天 / 反春**：各 ×2，与其他倍率相乘叠加（同一局不会同时出现）。
- **明牌 ×2、加倍 ×2、超级加倍 ×4**，可叠加。
- **叫分倍率 C** = 地主叫分（1/2/3）。
- **总倍数** = C × 炸弹/火箭 D × 春天/反春 E × 明牌 M × 加倍 X（不封顶）。
- **单份积分** = 底分 × 总倍数。**结算零和**：地主胜→地主 +3×单份、每名农民 −单份；农民胜反之。
- **积分不封顶**：全程高精度整数（`BigInt`）存储，客户端以 万/亿/兆/京 友好展示，真实值不截断。
- **允许负分**，无破产保护。
- **炸弹增强发牌**：目标炸弹总数按 `N(10, 1)` 取样；每个目标炸弹按 80% / 14% / 3% / 2% / 1% 选择 4 / 5 / 6 / 7 / 8 张。火箭独立按 5% 决定。预分配完成后，剩余牌重新洗牌并从当前牌最少者开始逆时针补发，保留 8 张底牌；补发仍可能自然形成新炸弹或增加已有炸弹张数。也可在房间设置中切换完全随机发牌。

### 发牌算法

房主可在房间设置中选择“完全随机”或“炸弹增强”：

1. 炸弹增强模式先按 `N(10, 1)` 生成目标炸弹数量，极端值限制在 6–14。
2. 每个目标炸弹按 80% / 14% / 3% / 2% / 1% 决定为 4 / 5 / 6 / 7 / 8 张，并随机选择普通点数。
3. 随机确定四位玩家各自获得的目标炸弹数量，再在不超过手牌容量的前提下分配。
4. 火箭以独立 5% 概率出现，并随机分给仍可容纳 4 张王的玩家。
5. 剩余牌重新洗牌，从当前牌最少的玩家开始逆时针补发，四家各补到 25 张，留下 8 张底牌。
6. 余牌补发可能自然形成新的炸弹，也可能增加预分配炸弹的张数；底牌没有禁止王、对子或炸弹。

线上权威实现位于 `public/js/cards.js`。

## 五、房间与排行榜

- 每个房间独立维护排行榜，不做全局排行榜。
- 统计维度：当前积分、胜/负、胜率、地主胜、农民胜、炸弹、火箭、春天/反春、最高单局倍数、最高单局积分、是否中途退出。
- 每局结算后更新；牌局进行中保持不变。达到总局数后展示最终排行榜。
- **中途退出**：退出玩家已结算积分保留在排行榜并标记「已退出」，后续局不再参与；进行中退出会暂停牌局，需房主解散。

---

## 六、断线重连

- 同一设备短暂断网时，浏览器 SSE 会自动重连；刷新页面时会使用本地保存的房间号和昵称恢复当前内存态牌局。
- 游戏进行中检测到真人离线会暂停计时和机器人动作；该玩家恢复连接后重新开始当前阶段的完整倒计时。
- 当前限制：只记录一个暂停发起者，多人同时离线时恢复判断不完整；换设备没有重连令牌；服务器重启不能恢复进行中的完整牌局。若长时间未重连，房主只能解散房间。

## 七、人机（AI 对手）

房间凑不满人也能玩：房主在**空座位上直接放人机**，1 个真人 + 3 个人机就能开局。

### 怎么用

| 操作 | 位置 | 限制 |
|---|---|---|
| 添加人机 | 房间等待页，**空座位**卡片上的「＋ 添加人机」 | 仅房主；仅未开局时；一桌最多 3 个（保证至少 1 个真人） |
| 移除人机 | 房间等待页，**人机座位**卡片上的「移除人机」 | 同上 |
| 开局 | 房主点「开始游戏」 | 人机默认**已准备**，不用一个个点准备 |

- 人机座位用**绿色卡片**区分，昵称后带「🤖 机器人」标记；牌桌座位上也有同款标记。
- 房间提示行会写明「还差 N 人满员 …… 也可以直接点空座位的『＋ 添加人机』补位」/「已满员（其中 3 个人机）」。
- 人机只在自己的座位上管理，**不会**和真人混在一起出现在「踢人 / 转让」按钮里；房主转让与房主离开都不会把房主身份落到人机头上。

### 人机会做什么

叫分 / 明牌 / 加倍 / 出牌 / 过牌全都自动决策，**思考延时 0.6–1.9 秒**（抖动的，不是固定值），读起来像真人节奏。出牌优先使用随游戏部署的人机模型，并叠加合法性与协作保护层。策略要点：

| 环节 | 依据 |
|---|---|
| 叫分 | 手牌牌力分（王/2/A/炸弹加权）对照阈值，会叫 1/2/3 分，也会不叫；4 家都不叫则流局重发 |
| 明牌 / 加倍 | 同理按牌力分决定「明牌 / 超级加倍 / 加倍 / 不加倍」，小牌不会乱加倍 |
| 出牌 | 1）能一把走完就直接走完；2）**农民不压自己队友**出的牌；3）跟牌只挑**最小能压过**的，不轻易拆 2 和王；4）对手快走完（或自己只剩一点牌）时才动炸弹，否则保留；5）领出优先走长牌型（顺子 / 连对 / 飞机），队友只剩 1 张牌时喂一张最小的单张 |
| 合法性 | 人机产出的**每一个**出法都要过一遍 `rules.js` 的权威校验（服务端还会再校验一次），不存在「人机出非法牌」的情况 |

### 实现方式

- 引擎是 `server/bot.js`，**零依赖、纯函数**：`genMoves()` 枚举全部合法出法、`server/model.json` 执行 `Coop-Bomb-v1` 纯 JS 前向，`chooseBid/chooseReveal/chooseMultiply/choosePlay()` 做决策。
- 人机运行文件为 `server/model.json`、`server/model.js` 和 `server/model-runtime.js`；不需要 Python、训练环境或外部依赖。
- 服务端调度只有一个入口 `Room.maybeBot()`：当前阶段该谁动作就排一次定时器，**同一时刻只存在一个思考定时器**（每秒的心跳广播不会堆积定时器）；牌局被「断线暂停」时人机也不动作。
- 阈值不是拍脑袋定的：用 5000 副牌统计牌力分位数（农民中位 ≈20、地主中位 ≈34），把叫分/加倍/明牌阈值放在对应分位上，测试里会断言这个关系不被改坏。

> 已部署模型负责主要出牌评分，启发式引擎负责兜底、合法性校验和极端局面保护。

## 八、音效 · 语音 · 局内互动

所有声音都由浏览器实时合成（Web Audio），**不需要任何音频素材文件**；语音报牌使用浏览器内置的中文语音合成。

### 声音

| 项目 | 说明 |
|---|---|
| 出牌 / 发牌 / 结算 | 出牌短响、发牌连响、胜负结算音 |
| 特殊牌型 | 炸弹=爆炸轰鸣、火箭=呼啸升天（同时触发爆炸/升天动画与全屏震动）；出牌的同时出牌者座位会有一记冲击环、桌面这一手牌会弹跳一下 —— **单出一个炸弹（首手自己领出）也同样有动画** |
| 语音报牌 | 每次出牌朗读**一次**牌型，如「一张3」「对2」「仨K带俩4」「顺子 3 到 尖」「4个9，炸弹！」 |
| 报播内容**不带昵称** | 所有语音（出牌 / 叫分 / 明牌 / 加倍 / 过牌 / 道具台词 / 接收者反应）都**只念内容本身**，不再在前面拼玩家昵称；「谁出的牌」只在界面文字（桌面提示牌、座位标记）里体现 |
| 过牌播报 | 有人过牌时会念一句「不要」；移动端显示在该玩家的出牌位置，桌面端保留头像气泡 |
| 叫分/加倍播报 | 有人叫分、明牌、加倍时会播报「叫三分」「不叫」「超级加倍」等 |
| 自己的操作**零延迟** | 按「不叫 / 2分 / 明牌 / 加倍 / 过牌 / 出牌」时，客户端会**立刻**用你自己的口音把这句话说出来，不再等服务端广播回来（省掉一个网络来回）；服务端广播到达时内容一致，会被 1.5 秒去重窗口吃掉，不会念两遍。队列空的时候是同步直接交给浏览器语音队列的，也省掉了进给节拍的等待 |
| 播报调度 | **立即开口 · 逐句完整**：浏览器一空闲就马上把下一条交给它朗读（队列空时是**同步交出**，0 等待），正在播的那句**一律不打断**，从头到尾播完才轮到下一条 —— 所以听不到半句话，也不会互相盖掉 |
| 播报优先级 | 自己发的快捷语/道具（最高）> 叫分·加倍·明牌 > 出牌报牌/过牌。优先级只影响「还没开始播」的那些的顺序，不会打断正在播的语音；队列积压时**整条丢弃**最不重要的一条 |
| 朗读用词 | 牌面代号转成中文读法（A=尖、K=凯、Q=圈、J=勾、10=十），中文语音引擎读起来不夹英文、更顺口 |
| **口音人设（随机分配）** | 每位玩家开局随机分到一种口音：**普通话 / 东北话 / 四川话 / 广东话 / 台湾腔 / English**，座位旁有一枚「🎙 口音」小标签。随机种子取自**房间号**，所以同一房间里每台设备算出的分配完全一致。口音分两层实现：① 音色 + 音调/语速；② 词表换词（「不要」→「别介 / 不要咯 / 唔要 / 不要啦」；English 人设整句翻英文） |
| **音源校对（不做假口音）** | **必须真音色才算数**：粤语、台湾腔、English 这三种口音只在**本机真的装了对应语言的语音包**时才启用；否则该座位改用本机说得出来的另一种口音，并**跳过该方言的换词表**（绝不会出现「标着粤语却在用普通话读『唔要』」这种错配）。座位的口音标签会如实显示成「🎙 广东话→普通话」，🅰 声音设置里的自检面板还会写明原因。东北话/四川话本质是普通话腔调，本机没有专用音色时按「模仿」处理并在自检里标注 |
| 音色挑选 | 自动挑选本机**最自然的中文音色**（优先 `Natural/Neural/Online` 一类神经音色，其次云端音色）；并且**不会把港台音色误当成普通话**（普通话音色用排除规则挡掉 `zh-HK / zh-TW / 粤语 / 英文` 音色）。首次点击页面时还会把各座位用到的音色**各预热一遍**，消掉第一句的起音延迟 |
| 背景音乐 | 四和弦循环轻音乐，进入房间后自动播放 |
| 音量调节 | 顶栏 **🔊** 按钮（面板在顶部栏正下方展开）只用于声音控制：**音效音量**（默认 100%）、**背景音乐音量**（默认 75%）、语音播报开关；设置会记住 |
| **发声自检**（🔊 面板内） | 显示「本机可用音色 N 个 / 中文音色 已安装 或 未检测到」，并逐个列出 4 个座位实际会用哪种口音（缺音色时会注明「改用这个 / 用普通话音色模仿」）。配「🔈 试听一句」与「↻ 重新检测」两个按钮 —— 手机上没声音时先点这两下 |
| 平台限制 | 同一个页面里 `speechSynthesis` **只有一条全局朗读队列**（Web Speech 规范如此，Chrome 也不支持在 iframe 里发音），所以多条语音**无法真正同时出声**，必然是依次播出。本项目做到的是：**谁也不用等谁的请求排队，一有空档就立刻开口，每句话都完整播完、绝不打断**。想要真正多人叠着说，只能改成播放音频文件的在线语音，本项目保持零依赖、离线可用，因此没有采用 |
| 移动端（iOS / Android） | ① 首次触摸页面即解锁音频与语音引擎；② iOS 会申明音频会话类型为 `playback`（Safari 16.4+），**手机开静音拨片时也能出声**；③ 从后台切回、从 bfcache 恢复时自动重新唤醒音频上下文，避免「切出去再回来就没声音」；④ 中文语音数据没装时（安卓常见）会**跳过**中文播报而不是念成乱码，并在自检面板提示去系统设置安装 |
| 浏览器限制 | 受自动播放策略限制，声音需在**首次点击/触摸页面后**才会响（正常操作下无感） |

### 局内互动（牌桌右下角三个并排按钮）

> 互动入口拆成右下角并排的三个圆按钮，各管各的：**😀 表情** / **🥚 道具** / **💬 快捷**。
> 三者互斥展开（点另一个会自动收起当前面板，再点一次收起）；顶部栏那行不再放互动按钮。

**😀 表情**（76 个，分「表情 / 手势 / 搞怪」三组）
点一下即发送，气泡显示在**自己的头像旁**。

**🥚 道具**（14 种，分「搞事情 / 送温暖」两组）
| 组 | 道具 |
|---|---|
| 搞事情（命中带💥） | 扔鸡蛋 🥚 / 扔番茄 🍅 / 扔白菜 🥬 / 扔拖鞋 🩴 / 扔大便 💩 / 砸冰块 🧊 / 泼冷水 🪣 / 放鞭炮 🧨 |
| 送温暖（命中带💗） | 送花 🌹 / 送礼物 🎁 / 敬杯酒 🍺 / 么么哒 💋 / 送钻石 💎 / 送皇冠 👑 |

先点道具，再点**目标玩家头像**（可点座位会高亮闪烁），道具会从自己飞向对方，命中后有爆点/特效、座位抖动与**各自专属的合成音效**（鸡蛋糊脸、玻璃脆裂、鞭炮连响、碰杯、号角……）。

**道具台词与反应**：用道具时会念出使用者台词（如「送你一朵小花」「请你吃个鸡蛋」），
道具**命中瞬间**接收者还会用**他自己的口音**回一句反应（攻击类：「哎哟，谁打我 / 过分了啊 / 我记住你了」；赠予类：「谢谢老板 / 嘿嘿，真香 / 你人真好」），同时显示在他头像旁的气泡里。
同一件道具的反应句按互动序号取，房间内所有人看到/听到的是同一句。（台词与反应都**不带昵称**。）

**💬 快捷指令**（24 条内置 + 可自定义）
分「礼貌 / 吐槽 / 玩梗 / 嚣张」四组，内置「666」「打得漂亮」「得得得得得得得得得得」「就这？」「你礼貌吗」「不要走，决战到天亮」等。
发送后显示气泡并**朗读**，朗读用的是**该玩家的随机口音**（见上表「口音人设」，可能是方言或英文）。
面板底部有「自己加一句」输入框，回车或点「＋ 添加」即可保存自定义快捷语（存本地，最多 12 条，条目后面的 ✕ 可删除）。

> 互动通过服务端广播，房间内所有人（含中途加入者）都能看到/听到；为避免刷屏做了 0.4 秒/人的发送间隔限制。

### 邀请好友

顶栏的 **📨 邀请**（房间等待页也有「📨 邀请好友」）会复制一段邀请信息到剪贴板，例如：

```
【斗地主】来打牌！房间「老张的牌局」房间号 123456，点这个链接直接进 → http://192.168.1.9:8080/?room=123456
```

> **链接一定是局域网地址，不会是 localhost。** 房主常常是用 `http://localhost:8080` 打开页面的，
> 而 `localhost` 链接发给别人是打不开的 —— 所以服务端启动时会把本机真实局域网 IP 随游戏状态一起下发给客户端，
> 客户端生成邀请链接时自动替换成 `http://<局域网IP>:8080/`（网段优先取 10.x / 192.168.x / 172.16–31.x，
> 自动排除 169.254 链路本地与 100.64/10 的 Tailscale/CGNAT 地址）。若当前访问地址本身就是局域网 IP，则原样沿用。
> 万一机器上没检测到可用局域网 IP，会照样复制并额外提示「好友可能打不开链接」。

发给微信/QQ 好友后，对方**点链接会直接跳到本房间**（若之前玩过、本地已有昵称，会自动加入；否则会预填房间号，填个昵称点「确认加入」即可）。链接里带了密码参数，有密码的房间也能一键进入。

## 十一、已知限制 / 后续可扩展

- 已支持真人托管；仍无逃跑惩罚、观战和比赛场。自由聊天未做，仅有内置快捷语。
- 人机已接入随游戏部署的模型，但仍不是完美 AI；启发式层会继续承担保炸弹、不压队友炸弹、合法性校验等保护职责。
- 一桌最多 3 个人机（至少留 1 个真人）；人机不会被踢、不能被转让房主、也不会被写成离线。
- 中途退出会暂停牌局，需房主解散（未实现「补位继续」）。
- 语音报牌依赖浏览器自带中文语音（Chrome/Edge/Safari 均支持；若系统没装中文语音包，本项目会**跳过**中文播报而不是念成乱码，并在 🔊 →「发声自检」里提示去系统里安装）。
- 浏览器里 `speechSynthesis` 只有**一条全局朗读队列**，**多条语音无法真正同时出声**（这是 Web 规范限制，不是实现问题），只能依次播出。本项目做到的是**立即开口 + 逐句完整**：一有空档就马上朗读新消息（队列空时是同步交出，0 等待），正在播的那句不打断、从头播到尾；想要物理上真正的并行发声，只能改用「在线语音合成 + 音频文件播放」，那样就必须联网且引入外部服务，本项目保持零依赖/离线可用，未采用。
- 需要真音色的口音（粤语 / 台湾腔 / English）依赖本机语音包：Windows 桌面版默认可能只有普通话（可到「设置 → 时间和语言 → 语言和区域 → 添加语言」里加装**中文(香港特别行政区)**等获得粤语），手机 iOS / Android 通常自带。装不上时该座位会自动改用别的口音并在界面标注，**不会假装成粤语**。
- 移动端针对横屏布局优化；iOS 浏览器不支持普通网页强制进入系统全屏，只能使用“添加到主屏幕”获得接近全屏的效果。
- 服务端房间运行状态以内存为主，重启后不能继续正在进行的牌局。对局事件会写入 `server/history` 便于故障排查和赛后分析，但目前没有历史查询界面。
- 仅监听局域网，不做公网/端口映射/内网穿透。
